## B12 的原因与修改范围

原始问法：“反射为什么会失去部分编译时检查，并带来性能与可读性上的代价？”

第 15 页不是召回不足：它包含 `reflection`，位于候选列表第 8，BM25 4.6433、最终分数 6.0363；第 10、14、9 页占据前三。旧逻辑只识别核心主题，中文属性没有被翻译为检索词；介绍 / API 页还获得主题标题加成。原始失败结果 [final-24-after-0.5.2.json](results/final-24-after-0.5.2.json) 保持原样，另保存 [原始排序诊断](results/b12-original-failure-diagnostics.json)。

检索运行时代码仅调整 `QueryPlan` 与 `KeywordIndex`；上述两项可靠性修复仅在 `RagAnswerService`：

- 原有主题识别保持不变，另标记通用的优点 / 缺点意图和性能、可读性、编译时、安全、副作用属性。
- 用这些词的 BM25 分数与意图覆盖度对已召回且匹配主题的候选重排。意图、属性不增加候选，不独立建立主题，也不放宽证据准入。
- 已分离的混合问题只从课程子句读取这些特征，避免无关子句的属性改变课程主题排序。
- 第六项验收补充通用约束：未识别课程主题时，除原有词汇覆盖条件外，去掉通用意图 / 属性词后的实质主题词也须达到原有 0.5 覆盖门槛。属性词本身不能充当主题依据；未收录但确有词汇支持的主题（如 recursion）仍可检索。
- 保留原有 BM25、0.10 分数门槛、0.5 词汇覆盖门槛、前三页 / 四片段和 5000 字符预算；没有新增模型、服务、文件名 / 页码 / B12 / Reflection 分支。

修改后 B12 的第 15 页排第一。异常处理“优点”问法同样改进，证明调整不限于反射。
