# 从 main 到 CourseMate AI 0.5.2 的修改说明（历史归档）

当前版本为 0.5.3，更新和测试结论见 [README_CN.md](README_CN.md)、[0.5.3 检索审查](evaluation/review-0.5.3.md) 及 [真实 API 检查](evaluation/live-review-0.5.3.md)。以下内容只描述 0.5.2 及之前的历史状态；其中“不自动重试”、B12 未命中、未进行真实 API 检查等结论不适用于当前版本。

本文记录截至 2026-10-27 的累计代码修改，供组员复核和后续提交使用。比较基线为 main / origin/main 的 `76962510a9599f40eea92ee63fd7a51d546ec513`，该提交的构建版本为 0.4.0，已经包含 Markdown、中英文回答及上一轮问答记忆。本文不把这些已有功能算作新增。

修改前已备份本地成果并 fetch 远端；远端仍为上述提交，合并检查返回 Already up to date。版本快照分支为 `hzy_0.5.2`，包含本文所列累计修改和验证记录；本文的比较基线不会随以后 main 的推进而改变。使用方法见 [中文 README](README_CN.md)，评测细节见 [评测 README](evaluation/README.md)。

## 修改目标和范围

从可演示的 F0 原型，改善为检索、连续追问、课程引用和交互更稳定的 Java 课程助教。保留 Swing、本地 PDF、BM25、来源白名单及已有测试；围绕实际缺陷调整请求、会话、模型响应和卡片数据，没有重建完整分层架构。

累计修改包含本地 0.4.1 的检索、启动器和 SDK 修复，0.5.0 的系统完善，0.5.1 的实测反馈修复，以及 0.5.2 的追问和交互修复。没有增加 embedding 服务、外部数据库、Web 前端、大型 UI 框架或第三方解析库。Java PSI 使用 IDEA 自带 Java 插件，并显式声明该插件依赖。

## 各模块的实际修改

| 模块 | main 中的行为 / 问题 | 当前实现 |
| --- | --- | --- |
| 检索请求 | 当前问句先检索，失败后拼接上一问；自然问法和代码措辞容易影响主题 | `ChatSession.Request` 先解析任务、主题和代码上下文；`QueryPlan` 形成概念查询，再召回、排序和判断证据是否足够 |
| 代码理解 | 代码特征与自然语言任务容易混杂 | `JavaSelectionContext` 用 PSI 分析明确选区的类型、调用及继承信息；不完整片段使用词法降级；不读取其他未选中源码 |
| 结果排序 | BM25 和固定覆盖判断容易漏检，也可能混入弱相关页面 | 保留 BM25，增加概念、标题、主题和 Java/C++ 相关性处理；候选与可用证据分开，同页互补块不因页级去重直接丢弃 |
| 多轮上下文 | 只保留上一问答，泛指追问可能逐渐取代原主题 | 当前主题、解析后问题、历史和代码快照结构化保存；先判断承接关系再检索，复合追问保持主题，明确新主题停止借用旧主题 |
| 代码沿用 | 缺少稳定、可见的跨轮选区管理 | 明确预览沿用的历史代码，可禁用或移除；新选区优先。历史仅帮助理解问题，每轮重新检索，不沿用旧引用 |
| 模型协议 | 业务结果主要是字符串，输出截断提示会污染原始 JSON | `ModelResponse` 分别保留正文、finish reason、usage；截断先于格式/引用校验处理，网络、HTTP、格式、引用和取消分别归类，无自动付费重试 |
| 代码解释提示 | 容易将选区不完整当成项目错误 | 明确选区可能只是项目片段，要求区分已知内容、推测和缺失信息，不猜测未提供方法的实现 |
| 来源可信度 | 普通 `.pdf` 文件名也可能被当作非法引用 | 保留本轮来源 ID 白名单；区分代码、正文和来源标记，普通文件名不直接判错；主要课程结论可关联各自的证据 ID |
| PDF 与缓存 | 空白清洗破坏代码换行；元数据不足以核对索引版本 | 保留必要换行和缩进，优先按段落、代码边界和整行切块；缓存 v3 保存文档指纹、稳定 Chunk ID、物理页码、规范化偏移、标题、块类型及邻接关系 |
| 证据包 | 同页有效片段可能丢失，候选容易被误作引用 | 按块召回并合并内容一致的重叠原文；证据受最多 3 页、4 块和 5000 字符预算限制；只有回答实际采用且通过校验的来源展示为引用 |
| 聊天展示 | 历史依赖拼接 HTML，回答、提示和来源层级不清楚 | 每轮独立 `TurnCard`，展开选区和原文、复制对应回答；课程部分与通用补充分开，固定显示来源区域和未引用原因 |
| 请求与语言 | 停止、迟到结果隔离及历史翻译管理不完整 | 真正取消网络任务，操作标识阻止迟到结果进入新会话；界面文案立即切换，历史回答按需翻译并缓存，代码和来源元数据受保护 |
| 启动与演示 | 需要手动设置运行环境和演示项目 | 新增双击启动器、环境检查、演示项目及启动器回归；仅对内置 demo 自动配置缺失/失效 SDK，已有有效 SDK 和普通项目保持原设置 |
| 测试组织 | 单元测试与真实教师 PDF 案例混在一起 | `test` 不需要教师 PDF 或真实 Key；`integrationTest` 单独执行 10 个真实讲义案例；测试进程移除 API Key |

查询理解仍依赖本地概念词汇与启发式规则，保留部分词法归一化和覆盖判断；没有实现通用语义理解。PDF 切块也不是完整的版面或 Java 语法解析，过长代码块仍可能分段。

## 0.5.2 修正类追问与交互反馈

用户反馈“修改后应该是什么样”得到“没有代码或上一轮内容”的回答。新增复现检查在修复前 4/4 失败：这类问题未被原有固定追问规则识别，导致请求阶段丢失代码和历史，并不是只需要调整提示词。

- 承接判断增加指代、修正结果及前后版本关系，同时结合明确选区的概念判断相关性。通用代码问题也可承接“那这里的泛型怎么改”；明显转向异常处理、继承或晚餐等新主题时不带旧代码。
- 发送前预览和实际请求共用同一承接判断。勾选允许沿用并不代表所有新问题都会带旧代码；若按新问题处理，输入区明确显示提示。
- 保留稳定主题的同时，把当前追问也加入检索请求；修正类问题携带原始代码快照和有界近期历史。建议的修改版本不会自动替换用户选区，更不会自动写入源码。
- 增加从会话、Swing 输入 / 预览到 HTTP 请求体的回归，检查完整选区没有被缩短、历史字段没有遗漏，且新选区和关闭沿用仍有效。
- 补强局部代码提示：先说明选区可见范围，完整语句判断要带条件；不能把缺少 `<>` 本身当语法错误，原始类型构造调用可以合法但产生类型安全警告。
- 蓝色卡片操作支持主题适配的正常、悬停、按下、选中、禁用及键盘焦点反馈，并显示手形光标；状态变化不改变字体尺寸或布局高度。

这些仍是本地、保守的关系判断，不能宣称所有自然语言指代都能正确识别。新增检查证明请求数据和界面状态正确，不证明真实模型一定遵循上下文。

### 采纳上下文管理建议后的补充修复

- 用不可变 `ChatSession.Context` 分开保存稳定主题、解析后问题、任务和会话关系。任务区分概念解释、代码解释、调试、示例扩展和代码建议；关系区分新主题、新选区、承接和明确纠正，不再用 FOLLOW_UP 同时代替任务类型。
- 修复历史队列串题：此前新主题首轮虽然不带旧历史，但提交后旧记录仍留在队列，下一次追问会重新带入。现在新主题 / 新选区提交时建立新的历史边界。
- 识别“我指的是……不是……”和英文明确纠正，解析用户当前重点；同一代码的澄清仍可沿用原始选区，改到不相关主题则移除旧代码。纠正轮不重复旧回答，成功提交后替换旧历史；用户纠正不成为课程证据或自动认定正确的事实。
- 请求明确携带 topic、resolved_question、task、context_relation，以及必要的选区和近期历史；每轮仍重新检索和校验引用。
- 继续保留最多 3 个完整历史轮次；预算不足时整轮省略并提示，代码原文独立保存。没有引入自动摘要、额外摘要模型调用、长期画像或跨会话搜索。
- 增加主题切换后再追问、纠正后再追问、任务 / 会话关系独立、显式换题、新选区边界和超预算完整省略的回归。用于追问承接的原有断言改为检查 Relation，同时增加实际 Task 断言，不删除原场景。

当前纠正识别只覆盖明确表达；含糊指代或未收录概念仍可能判断错误。失败 / 取消的请求不提交会话状态；重试时保留输入，不能把未完成的修正回答当作已确认历史。

## 按原始 F0 要求核对（0.5.2）

依据本地作业说明 PDF 第 1–2 页，A 类必做范围为 F0。原始 PDF 不随本仓库公开；下表为功能核对而非完整作业交付认证。

| F0 必需项 | 当前对应实现 | 验收边界 |
| --- | --- | --- |
| 预处理课程资料、分块和建立索引 | `PdfCourseReader`、`CourseChunk`、`CourseKnowledgeBase`、BM25 索引；界面显示讲义与块数量 | 已有真实 PDF 集成检查；不支持 OCR，超大代码块可能分段 |
| 检索相关块，与原问题一起提供给 LLM | `ChatSession.Request` → `RagAnswerService` → `DeepSeekClient`；保留原问题、解析主题、选区和每轮新证据 | 已检查实际 HTTP 请求构造；完整真实 API 人工验收仍未完成 |
| 课程回答明确引用文档及页码 / 范围 | 逐结论来源 ID、本轮白名单、文件 / 物理页码、原文快照及范围；展开原文和打开 PDF | 来源身份与范围可核对；结论是否受支持仍需人工检查 |
| 无课程依据时明确说明通用知识 | 回答依据与检索状态分开，固定来源区域说明未引用原因 | 未命中、候选不足、候选未采用及知识库故障不混为同一事实 |
| 友好界面嵌入 IntelliJ IDEA | 注册 Tool Window；独立卡片、输入 / 代码预览、停止、双语界面和有界会话记录 | 自动布局和状态测试已覆盖；仍需用户在实际主题 / 缩放环境观察 |
| 至少提供编辑器选区右键提问 | `AskCourseMateAction` 注册 `EditorPopupMenu`，选区快照经预览后发送 | 不自动读取未选中源码；片段不完整时不能断言整个项目编译失败 |

结论：六项必需能力均有代码实现，没有发现仍缺失的 F0 功能入口；不能据此说真实回答质量或整份作业已经全部验收。用户持续反馈的追问错误属于必须修复的可靠性问题，不因入口存在就算通过。

F1 的自动生成测试 / commit message / creative action 和 F2 的自动改源码 + 内置 diff 审批不属于 A 类必做项。本插件在回答中给出建议代码，不等于实现或需要实现 F2。英文报告 PDF、英文幻灯片 PDF、成员资料、源码 / 文档分目录的最终提交包仍按此前约定暂缓，不以 README 替代。

## 仍值得做的优化与可选功能

| 优先级 | 建议 | 当前处理 |
| --- | --- | --- |
| 最高 | 用真实 API 核对选区 → 修正追问 → 多轮承接，以及主要结论和引用原文的一致性 | 本地脚本最多 6 次，无自动重试；由用户另行运行，不拿 fake 通过代替 |
| 高 | 继续改善问题意图和证据覆盖，特别是优缺点 / 条件、复杂多主题及 B12 反射缺点漏检 | 本轮保留现有冻结结果，不针对其调参；下一轮应有新题集和相关页覆盖 / 逐结论证据标注 |
| 中，可选 | 对确实含糊的问句提供手动“承接上文 / 新主题”控制，降低启发式猜测影响 | 先收集实际失败问句；目前使用预览、新主题提示和新对话功能，不增加一排默认控件 |
| 中，可选 | 插件内选择课件目录、查看具体导入问题，减少依赖环境变量和启动参数 | 当前目录和索引状态可见；完整设置页不是 F0 硬性要求，暂未扩展 |
| 低，可选 | 用户明确需要时提供有限会话保存 / 导出 | 当前只在进程内保留；落盘涉及选区和课件原文，应先明确保存范围，不默认开启 |

不建议现在增加更多生成菜单、长期记忆、自动历史翻译或自动修复源码。Embedding / 混合检索只有在独立评测证明现有检索不足、解释依赖和成本后才考虑，不直接实施。

## 0.5.1 实测反馈修复

- 长回答按实际可用宽度计算高度，修复窄窗口和大字体下正文被按钮遮挡的问题；增加了宽度和字号组合的布局回归。
- 课程部分统一显示一次标题；段落证据、提示、状态和来源说明采用更弱的视觉层级。按钮改为轻量操作样式，继续使用 IDEA / Swing 主题。
- 删除“显示本语言回答”按钮；语言切换直接展示已有缓存译文。没有缓存时保留单条翻译入口，不自动翻译全部历史。
- 顶部增加“会话记录”，可回看并继续当前面板内最近 10 个会话；各自保存卡片、草稿和代码选择状态。关闭项目或面板销毁后不保留，旧版已经清除的记录不能恢复。
- 补充“再举一个例子，并说明实际调用哪个方法”等复合追问；模型请求明确携带解析后的问题及近期历史。
- 兼容单个完整 JSON 代码围栏、可空的非必需响应元数据和空的可选补充；空正文且 finish reason 为 length 时按截断处理。仍拒绝非法来源，不从任意杂文中提取 JSON。
- 格式失败分阶段显示安全提示，保留输入，并验证失败后可以继续提问。截图无法还原此前第三问的原始报文，真实问题仍需新版复测。

## 上下文、诊断和引用边界

每会话最多提供最近 3 个完整问答轮次给模型、展示 30 张卡片；问题上限 6000 字符、代码上限 16000 字符，总上下文上限 28000 字符。输入超限明确拒绝；按预算省略完整历史或证据时提示，不静默截断输入。

课程来源保存对应轮次的文档指纹、块 ID、原文范围和快照。重建索引不改写旧卡片；打开 PDF 前核对指纹，页码为从 1 开始的物理 PDF 页码。`#page=` 是否跳转由本机 PDF 阅读器决定。

原始异常和受限服务端响应仅留在进程内诊断字段，不写入磁盘日志或直接显示。来源白名单校验只证明引用身份合法，不能证明结论正确；回答与证据的一致性仍需人工核对。
